# 维护手册

日常维护主要看运营后台：`https://你的域名/admin?token=后台密码`

## 一、后台能看到什么

| 区域 | 用途 |
| --- | --- |
| 今日解析 / 成功率 / 平均耗时 | 判断服务是否健康，成功率掉到 90% 以下就要查 |
| 近 7 天趋势 | 看量有没有涨，哪天出过事故 |
| 失败原因 Top | 排错入口，同一错误扎堆说明规则变了 |
| 用户反馈 | 用户直接报的问题，比错误日志更直观 |
| 测试解析 | 改完配置立刻验证，不用开小程序 |
| 重启浏览器 / 清空缓存 | 两个最常用的应急按钮 |

平均耗时正常值：**200–600 ms**。超过 3 秒通常是页面加载变慢或网络问题。

## 二、常见故障与处理

### 1. 全部解析失败，后台错误显示「403 风控」或「Uifid」

抖音升级了风控。按顺序试：

1. 后台点「重启浏览器」，等 15 秒再测
2. 若仍失败，把 `config.json` 里 `parse.seed_aid` 换成一条**当前热门视频**的 ID
   （随便从抖音网页版复制一条视频链接，`/video/` 后面那串数字）
3. 还是不行，对照 `upstream/` 里的参数：

```bash
# 上游项目里维护着最新的请求参数
cat upstream/src/dtk/platforms/douyin/params.py | grep -A5 VERSION_CODE
```

把 `VERSION_CODE`、`VERSION_NAME`、`UPDATE_VERSION_CODE` 的值同步到
`server/core/browser.py` 的 `_FETCH_JS` 里。

4. 如果上游也更新了签名算法，同步 `core/signing/abogus.py`：

```bash
cp upstream/src/dtk/signing/native/abogus.py server/core/signing/abogus.py
# 改回相对导入
sed -i 's/from dtk\.signing\.native\.sm3/from .sm3/' server/core/signing/abogus.py
```

### 2. 只有部分视频失败

- 提示「作品不存在或已被删除」：真的删了或设了私密，正常
- 直播回放、付费内容、企业号特定内容：抓不到播放地址，属于能力边界
- 图集提示「没有可下载的内容」：可能是纯图文（无图集），可忽略

### 3. 提示「解析服务启动失败」

Chrome 没起来。检查：

```bash
# Linux
google-chrome --version
ls /usr/bin/google-chrome
# 内存够不够
free -h
```

`config.json` 里写死路径：

```json
"parse": { "chrome_path": "/usr/bin/google-chrome" }
```

### 4. 下载到 99% 卡住 / 保存失败

- 视频地址有时效（约 2 小时），后台缓存 TTL 默认 1800 秒，正常不会过期
- 用户网络差：小程序已做提示，让他重试
- 服务器带宽跑满：看 `iftop`，考虑升带宽或用对象存储中转

### 5. 内存越来越高

Chrome 标签页长时间运行会涨内存。做法：

- 后台点「重启浏览器」（每周一次即可）
- 或者加个定时任务：

```bash
# 每天凌晨 4 点重启服务
0 4 * * * systemctl restart douyin
```

## 三、要改文案 / 广告 / 次数怎么办

全部在后台改，**不用重新发版**：

- 公告 → 「小程序文案与服务」→ 首页公告
- 客服微信 → 同上
- 免责声明 → 同上
- 三个广告位 ID、免费次数、广告上限 → 「广告位与次数」
- 对外域名 → 「小程序文案与服务」→ 对外域名

改完保存，小程序下次启动（或重新进首页）就会拉到新配置。

要改**界面结构、颜色、流程**，才需要改代码重新提审。

## 四、数据与备份

```bash
# 解析记录、缓存、反馈
sqlite3 server/data/data.db ".backup backup/data-$(date +%F).db"

# 配置
cp server/config.json backup/config-$(date +%F).json
```

`data/data.db` 里三张表：

| 表 | 内容 | 会不会变大 |
| --- | --- | --- |
| parses | 每次解析的记录 | 会，1 万条约 2 MB，可定期清 |
| cache | 作品信息缓存 | 会，可后台一键清空 |
| feedback | 用户反馈 | 慢 |

清理三个月前的记录：

```sql
DELETE FROM parses WHERE ts < strftime('%s','now') - 90*86400;
VACUUM;
```

## 五、监控（可选但建议）

最简单的方案：用任意免费监控（UptimeRobot、腾讯云云监控）盯这个地址

```
https://你的域名/api/health
```

返回 `{"ok": true, "browser": true}` 即正常。
`browser` 变 false 就会自动告警，比用户报障早。

想更细一点，写个脚本每小时跑一次：

```bash
#!/bin/bash
r=$(curl -s https://api.yourdomain.com/api/health)
echo "$(date) $r" >> /var/log/douyin-health.log
echo "$r" | grep -q '"browser": true' || systemctl restart douyin
```

## 六、升级上游参考项目

```bash
cd upstream
git pull
```

上游更新后重点看这几处有没有变：

- `src/dtk/platforms/douyin/params.py` — 请求参数
- `src/dtk/signing/native/abogus.py` — 签名算法
- `src/dtk/urls/patterns.py` — 链接正则（抖音改域名时用得上）

## 七、风控与合规提醒

- 单 IP 请求太快会被限流，代码里已有每分钟 40 次的限制，别调太高
- 不要做「批量下载用户主页全部作品」这种功能，容易被判定为爬虫
- 不要在小程序里做「搬运教学」「二次上传教程」，这类是审核红线
- 收到权利人投诉时，后台反馈里能看到，及时下架相关能力

## 八、一次典型故障的排查顺序

```
1. 后台打开看「今日解析」和「成功率」
2. 点「测试解析」，粘一条抖音链接
   ├─ 成功 → 问题在小程序侧（域名白名单、网络）
   └─ 失败 → 看错误提示
       ├─ 403 / Uifid → 风控，重启浏览器 → 换 seed_aid → 同步参数
       ├─ 超时 → 服务器访问 douyin.com 是否正常：curl -I https://www.douyin.com
       ├─ Chrome 启动失败 → 查内存、查 chrome_path
       └─ 作品不存在 → 换一条链接验证，确认不是全局故障
```
